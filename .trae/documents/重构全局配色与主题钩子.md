## 改造目标
- 在主题钩子中引入可复用的色卡变量集合：相似色（Analogous）、中差色（Mid）、对比色（Contrast）、互补色（Complementary），每类可包含多个色。
- 自动限制饱和度与明度：避免过浅/过深；保证文本与背景达到可读性对比（参考 WCAG）。
- 根据深/浅背景与用户系统的白天/黑夜模式，为每类色卡生成亮/暗变体，并在 UI 中应用。
- 根据用户上传图片的色彩分布，完成类型化分类后映射到 UI 不同元素，保证“不同元素不同颜色”的清晰层级。
- 德语冠词 der/die/das 使用三种不同的中差色；焦点卡片背景使用主题主色的合适亮变体（或背景图占比最高色）。

## 技术方案
- 扩展调色盘 Schema：在 `extractPaletteFromImage` 的结果中增加：
  - `analogous: string[]`：±20–40° 的近似色集合，适度降饱和与调亮，适合背景/弱层级。
  - `mid: string[]`：与主色有中等差异（~60–120°）的色集合，用于次级强调与分组（冠词用）。
  - `contrast: string[]`：与背景有高对比（亮度/色相）的集合，用于按钮文字/标签/分隔线。
  - `complementary: string[]`：180° 互补色及其邻域，用于高亮/警示/强调。
  - `variants: { light: Record<string,string[]>, dark: Record<string,string[]> }`：上述四类的亮/暗变体；依据 `prefers-color-scheme` 与背景亮度自动选择。
  - 保留现有 `primary/secondary/accent/background/text/overlay` 字段以向后兼容。
- 分类算法：
  - 量化后得到 `sortedColors`（`src/utils/colorUtils.js:37-41`），以主色为锚；将其它簇转为 HSL 并按与主色的色相差距与亮度进行分配：
    - Analogous：色相差∈[20°,40°]，亮度∈[0.25,0.65]；降饱和（≤0.6）。
    - Mid：色相差∈[60°,120°]，亮度∈[0.30,0.75]；确保三色分散（用于 der/die/das）。
    - Contrast：基于与背景的对比度（亮度差、加权 YIQ/相对亮度）≥阈值，挑选 2–4 个。
    - Complementary：主色±180° 及±150°/±210° 邻域，亮度∈[0.35,0.80]。
  - 明暗变体：对每类生成 `light/dark` 集合，分别加/减明度并轻微调饱和度；保证 `0.20 ≤ L ≤ 0.85`，`0.35 ≤ S ≤ 0.90`。
- 主题钩子增强：
  - 在主应用新增/修复 `src/hooks/useTheme.js`（或统一复用 TS 实现），读取扩展后的调色盘；监听 `storage` 与 `prefers-color-scheme` 变化，动态切换 `variants.light/dark`。
  - 暴露 `theme.palette`（四类集合）与 `theme.roles`（元素角色 → 颜色策略），例如：
    - `roles.background = variants.dark.analogous[0]`（深色壁纸时）/`variants.light.analogous[0]`（浅色壁纸时）
    - `roles.textOnBg` 基于背景计算可读文本色（`src/utils/colorUtils.js:391-395`）；
    - `roles.buttonPrimaryBg = primary`，`roles.buttonPrimaryText = textOn(buttonPrimaryBg)`；
    - `roles.cardHeader = variants.current.contrast[0]`，`roles.border = withOpacity(contrast[0], 0.25)` 等。

## 元素颜色分配策略
- 背景与玻璃层：`analogous` 轻/暗变体提供柔和底色；`overlay` 基于主色的暗化（`src/utils/colorUtils.js:98-102,68-81`）但受亮度阈值限制。
- 文本：基于背景自动选择黑/白（`src/utils/colorUtils.js:391-395`）或提升对比度；标题/标签用 `contrast[0]`。
- 按钮：主按钮背景 `primary→secondary` 渐变（已有，`auth-app/src/hooks/useTheme.ts:45-49`），文本与边框取 `textOn(bg)` 与 `contrast`。
- 卡片：焦点卡片背景用主色的亮变体（替换 `#FAF9F6`，见 `src/components/Dashboard/views/WordCard.js:321-325`）；分隔线用 `contrast` 的低透明度。
- 冠词：`der/die/das` 分别使用 `mid[0] / mid[1] / mid[2]`，确保三色间色相距离均匀且亮度接近。

## 明/暗模式与可读性
- 检测：根据背景亮度与 `prefers-color-scheme` 决定当前模式。
- 约束：所有应用色在 L∈[0.20,0.85]、S∈[0.35,0.90]；对文本与关键 UI（按钮、徽章）使用对比度阈值（例如相对亮度比≥4.5:1）。
- 动态：模式切换时仅替换 `variants.current` 引用，避免全量重新计算。

## 图片取色分类流程
1. Downsample + 量化（已有，`src/utils/colorUtils.js:7-35`），得到 `sortedColors` 与频次。
2. 主色设为占比最高色（`src/utils/colorUtils.js:47-49`）。
3. 其余色簇转换为 HSL，按与主色的色相差距与亮度范围分配到四类集合；不足时用算法生成色相邻域补齐。
4. 为四类集合生成 `light/dark` 变体；将 `palette` 写回 `localStorage`（沿用现有机制，`src/components/Dashboard/views/ProfileView.js:75-80`）。
